=== DESIGN (decide details with evidence; reuse existing constructs) ===
1. LEAN TABLE (price of record): one row per (scope, security, price_type, date) with only what readers need — security id, date, price, currency, price type, source / provider (small code via a lookup, not repeated text), as_of, quality flag bits, licence code, adjustment factor, org_id (NULL = platform) — measure bytes/row and justify (target ≤ ~100 bytes incl. indexes). Partition by year if it measurably helps; BRIN or btree by evidence. RLS: platform rows readable as today; org rows only to their org — the same policies as today, proven both ways.
2. RESTATEMENTS: the superseded value of any restated close moves to a small history table (old value, valid/system times, provenance, upload / run); the lean row is always the current value. Every "what was the price as known at time T" query the platform makes today keeps its answer (find them; keep a function or view that answers it).
3. COMPATIBILITY: keep the old name working for readers through a view (security_invoker = true) exposing the old columns (bitemporal columns derived from lean + history) so no reader changes behaviour; switch the WRITERS (receptor / backfill / nightly / org uploads) to the lean table directly. The OHLCV `bar` jsonb moves to the archive only (say which readers used it, if any, and point them at the archive helper).
4. ARCHIVE: Parquet files in R2 (one prefix, partitioned by year; a daily append + monthly compaction step on the existing nightly job — no new service), written from the lean table; a small read helper (DuckDB in-process, reading R2 over the S3 API with the existing R2 credentials) returning a security × date frame. Prove parity with Postgres on fixtures. Switch the hypothetical backtest's history read to the helper ONLY if its reads are long scans (measure; else leave it and say so).
