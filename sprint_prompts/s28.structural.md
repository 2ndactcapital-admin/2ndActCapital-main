=== TASK 2: METRICS ===
services/ai_drift.py: for a task (and optionally an org) and two windows —
baseline (default the previous 28 days, excluding the recent window) and
recent (default the last 24 hours, plus a 7-day view) — compute calls, cost
per call (median, p95, total), latency (median, p95), fallback rate, failure
rate, bypass rate, effort downgrade rate, and the set of model_used values
(with first-seen time). Pure functions over rows plus one SQL read per
window; Decimal for cost.

=== TASK 3: RULES AND THRESHOLDS ===
Drift rules, each with a default threshold and a minimum sample (both
recent and baseline) below which the rule says "not enough data", never
alarms:
  - cost per call: recent median > baseline median × (1 + X), default 50 %;
  - latency: recent p95 > baseline p95 × (1 + X), default 50 %;
  - fallback rate / failure rate / bypass rate: recent − baseline > N
    percentage points, defaults 10 / 5 / 10;
  - effort downgrade rate up > N points, default 10;
  - model change: a model_used value in the recent window that the baseline
    never had (a silent provider swap / version change) — always an alert;
  - model mismatch: model_used ≠ model_requested without fallback_used
    (the router said one thing and another ran);
  - silence: a task with a baseline but zero calls in a window it normally
    has calls (optional per task, default off).
Thresholds live in a versioned settings table (platform defaults, optional
per-task override), editable by Super Admin only, every change a new version
with history and audit.
