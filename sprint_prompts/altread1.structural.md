CONFIRMED REAL FACTS — ALTRUIST'S PUBLISHED OPEN API, DO NOT RE-DERIVE (developer.altruist.com/docs, read 2026-11-11 through the operator's browser; the sprint has no network — these are the source):
- Auth (docs/open-api-authentication): OAuth 2.0 authorization code, user-scoped. Authorize: `https://oauth.stage1.altruistnet.tech/api/oauth2/authorize?client_id=…&scope=openid&redirect_uri=…&state=…` (path `/api/oauth2/authorize`; scope `openid`). Token: `POST /altruist-open-api/oauth2/token` (on the API host — the client's api_base already ends in `/altruist-open-api`, so token URL = api_base + `/oauth2/token`), form body: client_id, client_secret, code (authorization_code grant) or refresh_token (refresh_token grant), redirect_uri, grant_type, **token_type=id**. Response: access_token (1 h), refresh_token (**28 days**), expires_in, token_type. Redirect URIs must be fully qualified https, allowlisted per environment.
- Endpoints (docs/endpoints; resource pages): V2 `GET /api/v2/households` (the households page itself shows `GET /v2/households` — the portal is inconsistent: build the households path as a single constant, default `/api/v2/households` per the endpoints index, and record the discrepancy), `GET /v2/accounts`, `GET /v2/accounts/{account_id}/positions/`, `GET /v2/accounts/{account_id}/cost-basis/`, `GET /v2/accounts/{account_id}/transactions`. V1 (deprecating): `/api/v1/households`, `/api/v1/accounts/{household_id}`, `/api/v1/positions/{account_id}`, `/api/v1/cost-basis/{account_id}` — do NOT use V1.
- Headers: `Authorization` (the access token) required; `X-API-Request-ID` optional (send a uuid per request and log it — never a secret).
- Paging on every list: query `page` (default 0) and `page_size` (default 100; max 1000 for households / accounts / positions / cost-basis; **max 500 for transactions**). Response ENVELOPE (docs/json-code-examples): `{"paging": {"page": 1, "page_size": 25, "total_pages": 3}, "data": {"households": [...]}}`; accounts: `"data": {"household_id": "…", "accounts": [...]}`; positions: `"data": {"account_id": "…", "positions": [...]}`; cost basis: `"data": {"account_id": "…", "cost_basis": [...]}`. NOTE the example's paging.page is 1 while the parameter default is 0 — the client must page by `total_pages` and stop on an empty page, whichever base the server uses (prove both in the simulator).
- Households: query `name_pattern` (optional); fields id (required), name.
- Accounts: query `household_id`, page, page_size; fields id, rep_code, account_number, account_type (e.g. IRA, ROTH IRA, TRUST, INDIVIDUAL), account_name, status (ACTIVE, REJECTED, CLOSED, RESTRICTED, PENDING), date_open, date_closed, as_of_date, **account_balance**.
- Positions fields: id, cusip, symbol, description, long_short_indicator, currency_code, quantity, as_of_date, security_type (e.g. ETF, AGENCY, CORPORATE, MUNICIPAL, GOVERNMENT, TREAS…), market_value.
- Cost basis fields (one row per TAX LOT): id, cusip, symbol, description, quantity, market_value, cost_basis_unadjusted, cost_basis_adjusted, unrealized_gain_loss, as_of_date, open_date.
- Transactions: query `date_from`, `date_to` (YYYY-MM-DD; **default = the past month**), page, page_size (max 500); fields id, cusip, symbol, security_type (ETF, FI, OPTION, TBILL, INDEX, EQ, WARRANT, CASH, MBS, MUTUAL, CD, EQUITY, UNIT, OTHER), quantity, price, amount, interest, currency_code, **transaction_type** (e.g. BUY), transaction_subtype, transaction_description, cancellation_reversal_flag, **transaction_fees, broker_fees, other_fees**, TEFRA_withheld, state_tax_withheld, as_of_date, **transaction_date**, settle_date.
- DATES in the examples are `YYYY/MM/DD` (e.g. "2019/01/15", "2022/08/15"), not ISO; the transactions date QUERY parameters are YYYY-MM-DD. Parse both forms; send ISO in queries.
- Data is prior-business-day (end of day).
