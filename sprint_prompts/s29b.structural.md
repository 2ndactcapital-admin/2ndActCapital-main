=== TASK 2: AUTONOMY ELIGIBILITY ===
Each verb gets an autonomy class from 1a: `never` (money movement, custody,
authority, role / permission changes, trade submission, anything a floor
rule covers, anything contacting a member or outside party), `eligible`
(internal writes: tasks, notes, tags, document filing, draft proposals,
recalculations, data refresh, reminders), `eligible_with_cap` (writes with
a quantity — e.g. bulk updates — under a per-run cap). Stored on the verb in
the registry (reuse it — no new registry). A `never` verb can never run
unattended whatever a diagram says; validation refuses a trigger-started
workflow whose write step is `never` unless that step is Tier-1 (suspends
for a person).

=== TASK 3: SWITCHES ===
Org switch `workflows.autonomy` (OFF; org admin; maker-checker via S30;
audited) and per-workflow-version opt-in "may run unattended" (author_workflows
+ a checker; recorded on the version). Both must be on for any step to run
unattended. Turning either off stops new unattended steps at once (in-flight
runs finish their current step, then suspend for a person).

=== TASK 4: SHADOW PERIOD ===
Before a workflow version may run unattended it runs in SHADOW: every
would-be unattended write is recorded (verb, arguments, target, the result it
would have produced) but not executed; the owner reviews shadow runs; the
opt-in (Task 3) requires N clean shadow runs (org setting, default 3) and the
checker's sign-off. Shadow results live on the existing run / step rows
(reuse; state the columns).

=== TASK 5: EXECUTION, LIMITS, KILL SWITCH ===
When both switches are on and the step is eligible: the engine executes the
verb as the trigger owner's DELEGATE (audited "on behalf of <owner> by
workflow <name> v<n>"), with an idempotency key per run-step (a retry never
writes twice). Limits per org (runs / day, writes / run, writes / day,
eligible_with_cap caps) — over a limit the run HOLDS and alerts the owner and
org admin. A failure holds the run (no retry storm). A Super Admin platform
kill switch and an org kill switch stop all unattended execution
immediately. Tier-1 steps still suspend for a checker who passes
services/sod.py against the trigger owner.

=== TASK 6: EVENT TRIGGERS ===
Event-triggered runs (the event types from 1c, plus any internal events the
templates need — e.g. a document filed, a task completed, a held-away import
approved) follow the same rules; an event storm is de-duplicated (one run per
event per workflow version) and rate-limited.
