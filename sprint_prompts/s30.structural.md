=== TASK 2: THE DUTY MODEL ===
public.sod_duties: a duty per action class (e.g. propose_trade,
approve_trade, enter_held_away, approve_held_away, set_authority,
approve_authority, publish_disclosure, publish_model, approve_workflow_step,
author_workflow, configure_trigger, create_payee / bank instruction,
approve_transfer, edit_fee_schedule, approve_billing, manage_roles,
approve_role_grant, …) mapped from the permissions in 1b. public.sod_rules:
conflicting pairs ("the same person may not do A and B on the same item"),
with scope (same item / same household / same period) and severity (block
/ warn). Platform FLOOR rules (cannot be relaxed by an org: e.g. approve
your own trade, approve your own transfer, publish your own disclosure,
grant yourself a role) and org rules (stricter, editable by org admin with
maker-checker and history).

=== TASK 3: ONE SERVICE ===

record_decision(...) → the audit row. Persons, not logins (1c). Pure rule
evaluation + one read; deterministic.

=== TASK 5: SELF-APPROVAL, GOVERNED ===
Self-approval only where today's rules allow it (selfapproval.structural:
the eligible checker set is genuinely empty) AND the org's policy allows it
for that item type (default: today's behaviour). Every self-approval is
recorded with the reason "no other eligible checker", shown on the item, and
raises a compliance to-do; an org can turn it off per item type (then the
item waits). Platform floor items can never be self-approved.

=== TASK 6: CONFLICTING ROLES ===
When a role or permission set is granted, the SoD matrix is checked for the
person: a combination that lets one person both make and check the same
item type is flagged (warn) — with the rules that will still stop them per
item — and a floor conflict on role management itself (granting yourself a
role) is blocked. A report lists every person whose roles combine
conflicting duties.

=== TASK 7: NO BEHAVIOUR CHANGE BY DEFAULT ===

a fixture replay of today's allow / refuse decisions gives the same answer
through services/sod.py. Any site where the floor rules would change a live
decision is reported (not silently tightened) and left behind an org switch
"sod.enforce_floor" (default true only where today already refuses).
