## 2. Design (as built)

* `services/rebalance_schedule.py` — `daily_tick(pool, now_utc=)` (the tick step; never raises) → per non-test org with an opted-in link → `org_daily(pool, org_id=, now_utc=, include_test_orgs=False, prices_scope='platform')`.
* Day row `public.rebalance_schedule_days` UNIQUE (org_id, run_day): status waiting → running → completed | failed; readiness recorded (prices day / status / partial flag / oldest valuation date; nightly ok); counts; per-account results with reasons; errors; the summary to-do ids; `is_fixture`. A lease so two ticks never run one day.
* Org settings: `replication.schedule.run_time` (default 07:30 New York), `replication.schedule.prices_fallback_time` (default 10:00 New York).
* Selection: opted-in = link's own `rebalance_frequency` or `drift_threshold` set. Skips with reasons: closed, restricted (authority refusal), advice-only, long/short, model without approved version, open proposal, nothing to trade. Drift over the link's threshold → trigger `drift`; else frequency due (last proposal for the link group older than the period: daily = any earlier NY day, weekly 7 d, monthly 1 month, quarterly 3, semiannually 6, annually 12) → trigger `scheduled`.
* Generate: `RP.generate(trigger, maker_kind='system')` under `RP.account_lock` with the open check inside. Never approves / executes / sends.
* Summary to-do: one per approve_proposals holder per org per day, source `rebalance_schedule`, related_type `rebalance_schedule_day`.
